# 索引

## 索引的分类

DBMS渊远流长、博大精深，此笔记仅记录一些粗浅的概念理解，用于辅助日常开发判断，不作为任何专业判据；数据库默认为MySQL 8.0、InnoDB。

按照数据结构维度划分，索引可以分为
- BTree索引，MyISAM和InnoDB都是用B+树实现的
- RTree索引，效率较低，一般不用
- 全文索引，效率较低，一般不用
- 哈希索引

按照索引结构和数据是否一起存放划分，索引可以分为聚簇索引（聚集索引）和非聚簇索引（非聚集索引）。

按照应用维度划分，索引可以分为主键、普通、唯一、覆盖、联合、全文、前缀、隐藏、降序、函数索引等。一般的业务不一定会用到所有的索引。

## 索引的优缺点

## 主键索引、二级索引

InnoDB中，主键索引（primary key index）是聚簇索引（clustered index），同时也是该表的底层物理存储结构。聚簇索引（B+树）的叶子结点存储的是行的具体内容。每张表有且仅有一个聚簇索引。建表时，聚簇索引按照下面的顺序确定：
- 若某一个列组合声明为PRIMARY KEY，那么它是主键，且该主键就是该表的**聚簇索引键**，或简称该表的**聚簇索引**
- 若缺少PRIMARY KEY列组合，则第一个声明了UNIQUE NOT NULL的列组合是该表的聚簇索引
- 若缺少UNIQUE NOT NULL列组合，则自动创建一个占6字节的DB_ROW_ID列作为该表的聚簇索引

注：聚簇索引键是聚簇索引这一数据结构的排序和查找依据，习惯上合并称呼为索引。

除了聚簇索引外的索引，称为**非聚簇索引（non-clustered index）**，或**二级索引（secondary index）**，它也是B+树。在InnoDB语境下，更常用二级索引的叫法。“二级索引”的“二级”指的是相对于主键索引的第二类索引，其主要用途是提高检索效率，因而二级索引还可以称为**辅助索引**。后面的笔记统一称为二级索引。

二级索引与聚簇索引的关键差异是其叶子结点不存储行的内容，而是存储该二级索引键和主键的组合。当选择用该二级索引进行检索时，系统先在二级索引上找到对应叶子结点，如果要检索的目标列就在该叶子结点的索引数据中，那么就可以直接取出其值；若不存在，则需要**回表**：从该叶子结点中取出主键，再在聚簇索引（主键索引）上找到其对应的完整数据行。

主键索引与二级索引的另一个差异是，二级索引（除了唯一索引）不要求值的唯一性。假设表user上建立了二级索引`idx_name(name)`，要执行下面的查询语句：

```sql
SELECT * FROM user WHERE name = '张三';
```

由于idx_name上可能存在多个name为同一值的叶子结点，不能在找到第一个满足name为张三的叶子结点就结束，而是沿着叶子结点之间的链表，找到所有name为张三的叶子结点。在找到所有叶子结点之后，需要对**每一个**叶子结点上的主键分别回表（注意`SELECT *`）。这种扫描过程称为**范围扫描（Range Scan）**。

当数据量足够大，且二级索引不包含所要求的列时，就会出现大规模的回表。若有20万条name为张三的数据，就可能要进行20万次回表。此时优化器可能基于统计数据放弃使用索引，转而使用全表扫描。这表明索引并不一定都能起到正向的作用；索引的优化效果综合取决于查询语句、索引键、主键等因素。分析索引是否起作用是EXPLAIN语句的关键用途之一。

此处注意：聚簇索引上，name全为张三的叶子结点是连续的。检索过程从第一个name为张三的叶子结点开始，扫描到第一个name不是张三的叶子结点为止。

## 覆盖索引

如果一个二级索引的叶子结点包含了查询所需要的所有列，就不需要进行回表。
